# LLM 文档分析模块

## 核心设计思路

### 1. 文档分析的关键挑战

```
页面分析挑战示意:
+----------------+     +----------------+     +----------------+
|    Page 1      |     |    Page 2      |     |    Page 3      |
|  Title L1      |     |  Content...    |     |  Title L?      |
|  --------      |     |                |     |  --------      |
|                |     |  Table Start   |     |  Table Cont... |
|  Content...    |     |  | A | B |     |     |  | C | D |     |
|                |     |                |     |                |
|  Footer        |     |  Footer        |     |  Footer        |
+----------------+     +----------------+     +----------------+
      ↓                      ↓                      ↓
   挑战点:                挑战点:               挑战点:
   - 标题层级确定         - 表格起始判断         - 标题层级不明
   - 页脚模式识别         - 内容连续性           - 表格连续性
```

### 2. 内容结构化策略

在文档分析中，我们不仅关注显式的格式特征，更要注重内容的结构化组织：

1. **结构化目标**
   ```
   原始文档 → 结构化文档
   [密集文本]   [清晰层级]
   [少量标题] → [合理分段]
   [连续内容]   [易于导航]
   ```

2. **标题识别策略（尤其是原来标题质量差的，好的可以忽略）**
   - 在内容密集区域寻找结构化机会：
     * 编号段落（如 1.1、14.2 或类似的编号， 中文的或字母的）可作为潜在标题
     * 短小精炼的内容概述可提升为标题
     * 利用自然段落分隔标记层级
   - **平衡结构粒度**：
     * 避免过于稀疏（难以导航）
     * 避免过于密集（失去层次感）

3. **应用场景**
   ```
   典型案例:
   合同文档：条款编号 → 章节层级
   技术文档：步骤编号 → 操作层级
   报告文档：要点编号 → 内容层级
   ```

### 3. LLM分析能力评估

```
分析能力分布:
可靠度    项目                        特征
↑
高  |    页眉页脚    <-- 位置固定、格式统一、重复性强
    |    表格边界    <-- 明确分隔符、格式规范
    |    基本标题    <-- 明显格式特征
    |    
中  |    标题层级    <-- 需要上下文支持
    |    表格连续    <-- 需要语义理解
    |    段落关系    <-- 需要逻辑推理
    |    
低  |    复杂结构    <-- 深层嵌套、特殊格式
    |    跨页语义    <-- 长距离依赖
↓   |    特殊处理    <-- 非标准情况
```

### 4. 解决方案设计

```
处理流程示意:
[原始文档] → [预处理] → [LLM分析] → [结构化数据] → [后处理] → [最终文档]
   ↓            ↓           ↓             ↓            ↓           ↓
  PDF        添加标记   识别关键元素   DocumentAnalysis  层级优化    Markdown
  Word       规范格式   生成分析结果                    表格合并
  Scan       ...       ...                           内容清理
```

1. **数据结构设计原则**
   ```python
   class DocumentAnalysis(BaseModel):
       heading_infos: List[HeadingInfo]     # 标题信息优先
       remove_actions: List[RemoveAction]    # 删除操作
       merge_actions: List[MergeAction]      # 合并操作
   ```

2. **分析策略**
   - 标题：完整性优先，保留可能的标题
   - 页眉页脚：基于位置和重复模式
   - 表格：基于格式标记和内容连续性

3. **后处理设计**
   - 标题层级：使用传统算法优化
   - 表格合并：基于行列对齐
   - 内容清理：基于位置信息

   # LLM可以通过以下特征识别

   - 格式特征：与正文明显不同的格式

2. **表格识别**
   ```python

   - 表格边界：| 和 --- 标记

   # LLM可以识别

   - 内容特征：短语结构、关键词
   - 位置特征：段落起始、空行包围
   ```

## 处理流程设计

```
详细流程示意:
1. 分析阶段
   Document → [预处理器] → 带标记文档
                ↓
   上下文信息 → [LLM分析] → 结构化数据
                ↓
   验证规则  → [结果验证] → 确认结果

2. 处理阶段
   确认结果 → [清理处理] → 无页眉页脚文档
              ↓
   规则集   → [结构处理] → 结构化文档
              ↓
   格式模板 → [格式处理] → 最终文档
```

### 1. 分析阶段
1. **文档预处理**
   - 添加行号标记
   - 标记页面边界
   - 提取前序上下文

2. **LLM分析**
   - 生成结构化分析结果
   - 记录置信度信息
   - 保留可能的备选项

3. **结果验证**
   - 检查数据完整性
   - 验证位置信息
   - 确认格式合规

### 2. 处理阶段
1. **清理处理**
   - 删除页眉页脚
   - 规范化空行
   - 清理冗余格式

2. **结构处理**
   - 合并跨页表格
   - 调整标题层级
   - 优化内容布局

3. **格式处理**
   - 统一标题格式
   - 规范化表格
   - 优化空白处理

## 最佳实践
