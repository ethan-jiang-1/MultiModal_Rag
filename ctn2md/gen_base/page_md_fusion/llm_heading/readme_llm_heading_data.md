# LLM Heading 数据结构设计说明

## 一、核心设计思路

### 1. LLM判断与传统逻辑分离
- LLM职责：
  * 内容本质判断（标题/页眉页脚/正文）
  * 标题层级关系判断
  * 提供判断依据和置信度
  * 保持判断的独立性

- 传统逻辑职责：
  * 根据判断结果执行修改
  * 保证修改的一致性
  * 维护文档结构完整性
  * 处理错误和异常情况

### 2. 聚焦核心任务
- 主要目标：
  * 标题层级的识别和修正
  * 页眉页脚的识别和处理
- 明确不处理：
  * 表格相关的任务
  * 复杂的格式处理
  * 非必要的样式调整

### 3. 判断依据要求
- 标题判断：
  * 编号格式（如 1.2.3）
  * 内容特征（长度、语义）
  * 上下文关系（章节结构）
  * 位置特征（缩进、空行）

- 页眉页脚判断：
  * 位置特征（页面顶部/底部）
  * 重复模式（跨页一致性）
  * 内容特征（页码、文档标题）

## 二、数据结构设计

### 1. 核心数据模型
```python
class HeadingErrorType(str, Enum):
    """标题问题类型"""
    WRONG_LEVEL = "wrong_level"        # 是标题但层次错误
    NEEDS_LEVEL = "needs_level"        # 应该是标题但没有层次
    NOT_HEADING = "not_heading"        # 被误认为是标题但实际是正文

class HeadingAnalysis(BaseModel):
    """标题分析结果"""
    page: int                          # 页码
    line: int                          # 行号
    content: str                       # 标题内容
    current_level: Optional[int]       # 当前层级（如果有）
    expected_level: Optional[int]      # 应该的层级（如果应该是标题）
    error_type: Optional[HeadingErrorType]  # 问题类型
    confidence: float                  # 判断的置信度
    related_headings: List[int]        # 相关标题的索引（特别是跨页情况）

class RemoveInfo(BaseModel):
    """需要移除的内容（页眉页脚等）"""
    page: int                          # 页码
    lines: List[int]                   # 可能跨多行
    remove_type: str                   # "header" 或 "footer"
    confidence: float                  # 判断的置信度

class DocumentAnalysisHeading(BaseModel):
    """文档分析结果"""
    headings: List[HeadingAnalysis]    # 标题分析列表
    remove_markers: List[RemoveInfo]   # 需要移除的内容
    structure_warnings: List[str]      # 结构性警告
```

### 2. 关键设计决策
- 标题分析设计：
  * 保留原始和期望层级 → 支持可逆操作
  * 记录相关标题索引 → 处理跨页关系
  * 包含置信度和错误类型 → 辅助决策

- 页眉页脚设计：
  * 支持多行处理 → 完整性
  * 简化数据结构 → 聚焦移除操作
  * 包含置信度 → 控制处理策略

### 3. 典型场景示例
```python
# 标题判断示例
{
    "content": "1.2 系统架构",
    "judgment": {
        "is_heading": true,
        "level_analysis": {
            "current": None,
            "expected": 2,
            "reason": "二级章节编号格式 (1.x)",
            "context": "在 '1. 系统概述' 的层级下"
        },
        "confidence": 0.95
    }
}

# 页眉页脚判断示例
{
    "content": "文档标题 - 第1页",
    "judgment": {
        "is_header": true,
        "reason": "页面顶部固定格式",
        "pattern": "标题+页码组合",
        "confidence": 0.98
    }
}
```

## 三、关键实现考虑

### 1. LLM判断规则
- 标题判断规则：
  * 优先使用明确的格式特征
  * 考虑上下文的章节关系
  * 验证内容的合理性

- 页眉页脚规则：
  * 检查位置的一致性
  * 验证内容的重复性
  * 分析格式的特殊性

### 2. 跨页处理策略
- 标题跨页：
  * 记录相关标题索引
  * 验证章节结构连续性
  * 处理页尾标题延续

- 页眉页脚跨页：
  * 验证模式一致性
  * 处理特殊页面（首页等）
  * 标记异常情况

### 3. 置信度策略
- 高置信度 (>= 0.95)：
  * 可自动处理
  * 明确的页眉页脚
  * 标准格式标题

- 中等置信度 (0.85-0.95)：
  * 需上下文验证
  * 可能需人工确认

- 低置信度 (< 0.85)：
  * 必须人工审核
  * 可能需额外信息

## 四、补充说明

### 1. 边界情况
- 特殊页面处理：
  * 封面页
  * 目录页
  * 参考文献页

- 特殊标题处理：
  * 无编号标题
  * 跨页标题
  * 异常格式标题

### 2. 错误处理
- 处理优先级：
  1. 高置信度的页眉页脚
  2. 高置信度的标题问题
  3. 需要验证的情况
  4. 需要人工处理的项目

- 安全策略：
  * 保存中间状态
  * 支持回滚操作
  * 完整的日志记录 

## 五、处理流程

### 1. 总体流程
```
[输入文档]
    ↓
[预处理]
    ↓
[LLM分析阶段]
    ↓
[结果验证]
    ↓
[修正执行]
    ↓
[输出结果]
```

### 2. LLM分析阶段详细流程
```
[获取页面内容]
    ↓
[页眉页脚识别] → 高置信度直接处理
    ↓            中低置信度进入待验证池
[标题识别]
    |→ 单行判断：判断当前行是否为标题
    |→ 上下文分析：考虑章节结构
    |→ 跨页分析：处理跨页标题
    ↓
[层级分析]
    |→ 编号分析：根据标题编号推断层级
    |→ 结构分析：根据文档结构推断层级
    |→ 内容分析：根据标题内容推断层级
    ↓
[关系构建]
    |→ 记录标题间关系
    |→ 标记跨页关联
    ↓
[结果整合]
```

### 3. LLM提示策略
- 分步提示：
  * 第一步：识别页眉页脚
    ```
    判断依据：
    - 位置特征（是否在页面顶部/底部）
    - 重复模式（是否跨页重复）
    - 内容特征（是否包含页码/文档标题）
    输出要求：
    - 明确指出是否为页眉页脚
    - 提供判断依据
    - 给出置信度
    ```
  
  * 第二步：识别标题
    ```
    判断依据：
    - 编号格式（是否符合章节编号规范）
    - 内容特征（长度、语义特征）
    - 位置特征（缩进、空行）
    - 上下文关系（与相邻内容的关系）
    输出要求：
    - 明确指出是否为标题
    - 当前层级（如果有）
    - 建议层级（如果需要调整）
    - 提供判断依据
    - 给出置信度
    ```

### 4. 结果验证流程
```
[验证入口]
    ↓
[置信度分流]
    |→ 高置信度 (>=0.95) → 直接处理
    |→ 中等置信度 (0.85-0.95)
    |   |→ 结构验证
    |   |→ 一致性检查
    |   └→ 通过后处理
    |→ 低置信度 (<0.85) → 人工审核
    ↓
[结构完整性检查]
    |→ 层级连续性
    |→ 章节完整性
    |→ 跨页一致性
    ↓
[异常处理]
    |→ 记录警告信息
    |→ 生成修正建议
    |→ 标记待处理项
```

### 5. 关键流程原则
- LLM分析原则：
  * 单一职责：每次只关注一个判断任务
  * 明确依据：清晰列出判断的依据
  * 可追溯：保留判断的推理过程
  * 置信度量化：为每个判断提供置信度

- 验证原则：
  * 渐进式：从高置信度到低置信度
  * 多维度：结合多个特征进行验证
  * 可回溯：保留验证过程
  * 人机协作：适时引入人工审核
